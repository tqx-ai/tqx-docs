Qube runs strategy source through a market-specific backtest engine. Keep the run's dates, capital, frequency, and costs in saved configuration.

## Minimal source

Qube's Python backtest engine provides the `panda_backtest` modules. See the [APIs in strategy code](/qube/research/strategy/api) for orders, cancellations, order queries, and market history methods.

This Hong Kong example reads completed Bars without placing orders. For US strategies, use `stock_us_api` and a symbol such as `AAPL.NB`.

```python
from panda_backtest.api.api import *
from panda_backtest.api.stock_hk_api import *

STRATEGY_PARAMS = {"symbol": "0700.HK"}

def initialize(context):
    context.params = dict(STRATEGY_PARAMS)

def handle_data(context, data):
    bar = data[context.params["symbol"]]
    if bar is None or bar.open is None or bar.open <= 0:
        return
    context.latest_open = bar.open
```

Use one literal `STRATEGY_PARAMS` dictionary. Copy it to `context.params` exactly once in `initialize`; tuning uses declared and referenced numeric keys. Strategy validation rejects direct `tqx_data` imports, including aliases, submodules, and from-imports. Use the public `panda_backtest.api.api` and same-market `stock_hk_api` or `stock_us_api`. Native `tqx_data` remains available for sandbox exploration.

## Historical data and replay

Batch and cache history from before the backtest starts, then combine it with completed Bars during replay. See the [APIs in strategy code](/qube/research/strategy/api#historical-data) for query methods, parameters, and Bar access rules.

## Orders and costs

Use the common order APIs to place, cancel, and query orders, and confirm fills through callbacks. See the [APIs in strategy code](/qube/research/strategy/api#orders) for parameters, order styles, and matching rules.

For bound factors, use only data available at the decision time; see [factor binding](/qube/research/strategy/factor-to-strategy).
