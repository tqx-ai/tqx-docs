A **run** is one attempt to execute a factor analysis or strategy backtest. Each run keeps the code and settings used at its start, together with its status and results. Editing today's strategy does not rewrite yesterday's run.

## Find the right run

Open the factor or strategy and inspect its analysis or backtest history. Check the start time, date range, and settings so you know which experiment you are reading.

For example, a Tencent backtest with a 20-day buy rule and one with a 15-day buy rule are two different experiments. If you also changed the fees, the result cannot tell you how much of the difference came from the rule alone.

## Understand the status

| Status                  | What it means                     | What to do                                                 |
| ----------------------- | --------------------------------- | ---------------------------------------------------------- |
| Preparing (`preparing`) | Inputs are being prepared.        | Wait and return to the same run.                           |
| Queued (`queued`)       | Waiting for execution.            | Do not submit a duplicate just because it has not started. |
| Running (`running`)     | The calculation is in progress.   | Treat any visible charts as incomplete.                    |
| Succeeded (`succeeded`) | Execution completed successfully. | Review the inputs, results, and limitations.               |
| Failed (`failed`)       | Execution ended with a problem.   | Read the error and logs before retrying.                   |
| Cancelled (`cancelled`) | Execution was cancelled.          | Do not interpret it as a completed test.                   |

A stop request can take time to finish; check the final status. A local waiting timeout does not cancel the remote run. Keep the run's identifier if you need to return to it through the CLI or SDK.

## Compare like with like

Check the stock or stock pool, dates, starting capital, costs, benchmark, and rules. Change one choice at a time when you want to explain its effect. Then compare both the ending result and the losses along the way.

A successful run means the calculation finished, not that the idea is profitable or reliable. Ask Qube to explain missing data, rejected trades, and unusual periods before drawing a conclusion.

## Keep or restore a useful result

A named version preserves the inputs from a successful ordinary run. Restoring an old version or run replaces your current working inputs; it does not alter the old result or automatically start a new calculation. Review the restored settings before running again.

For technical details on identifiers, result paging, incomplete charts, cancellation, and restore commands, see the [Runs API](/qube/api/runs) and [SDK progress guide](/qube/sdk/streaming).
