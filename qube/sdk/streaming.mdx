Use polling to check progress at regular intervals. Use SSE (server-sent events) to receive updates over a continuous connection. Initialize the [TypeScript SDK](/qube/sdk/overview) before using the examples below.

## Polling

```typescript
const result = await client.research.pollFactorAnalysis(analysisId, {
  interval: 2,
  timeout: 600,
  progressCallback: value => console.log(value.status),
})
```

Polling stops on succeeded, failed, or cancelled. A timeout returns the latest resource with a timeout marker and does not cancel the server task.

## SSE protocol 1

```typescript
const controller = new AbortController()
for await (const event of client.research.streamBacktest(runId, {
  signal: controller.signal,
})) {
  console.log(event.event, event.seq, event.value.status)
}
```

The SDK uses protocol 1: each event's `value` contains a complete status snapshot. Events include `snapshot`, `done`, `error`, and `cancelled`. Pass the last sequence as `after` when reopening a stream. The SDK does not reconnect automatically. Abort the `signal` when the user leaves the page or cancels local work.

## Error handling

Catch TqxNetworkError for transport failures, TqxApiError for server responses, TqxProtocolError for malformed response or SSE data, and TqxValidationError for input or schema failures. A remote failure is different from a local timeout; keep the run ID for later inspection.

## Other streams and terminal behavior

`streamFactorAnalysis`, `streamBacktest`, `streamFactorTuning`, and `streamStrategyTuning` each return an async iterable of `{ event, id, seq, value }`. Stream terminal events close the iterator. The `done` SSE event is not a run status; ordinary run success remains `succeeded`.

Polling options use seconds: `interval` defaults to 2 and `timeout` defaults to 600. A timeout adds `cli_status: "TIMEOUT"` and `timeout_seconds` to the latest result. Check both terminal state and the timeout marker. Aborting a stream stops reading locally; explicitly call the matching cancellation method to request server cancellation.

On a network interruption, preserve the last `seq` and reopen with `{ after: lastSeq, signal }`. Handle failures and terminal snapshots before deciding whether another connection is appropriate. Reusing a request ID is only safe with an identical mutation body.
