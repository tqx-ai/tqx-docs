Qube separates what you are editing from what you have already tested. This lets you improve an idea without losing the settings behind an earlier result.

## Follow one strategy through the workspace

Suppose you save a Tencent strategy that buys after a 20-day price breakout:

1. **Strategy:** the working rules and settings you can edit.
2. **Run:** one backtest of those rules over particular dates, with particular costs and starting capital.
3. **Named version:** a fixed, named copy of the inputs from a successful ordinary run, such as “20-day baseline.”

Now change the buy window to 15 days. Your current strategy changes, but the old backtest still records the 20-day rule. A new backtest gives you a separate result to compare with it.

## A short glossary

| Term          | Meaning                                                   | Example                                                        |
| ------------- | --------------------------------------------------------- | -------------------------------------------------------------- |
| Factor        | A rule that scores stocks.                                | Rank stocks by recent price strength.                          |
| Strategy      | Rules for buying, selling, and position sizes.            | Buy a breakout and exit below an average.                      |
| Run           | One analysis or backtest using fixed inputs.              | Test the strategy over a three-year period.                    |
| Named version | A preserved set of inputs from a successful ordinary run. | Keep the original rule before trying a change.                 |
| Tuning        | A comparison of a limited set of parameter choices.       | Compare different lookback windows with the original settings. |

Saving work, running a test, and creating a version are separate actions. Ask Qube which action it completed and open the saved result to check.

## What does a revision mean?

A **revision** is a change counter. Qube tracks code changes and settings changes separately. This helps detect when another edit has happened before a new change or run uses the old information.

The web workspace handles these checks. If you build an integration yourself, read the current revisions and use the expected values described in the [API reference](/qube/api/runs). Identifiers, request IDs, and result paging are integration details; you do not need them to start a web conversation.
