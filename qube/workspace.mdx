Your Qube workspace lives in a separate Linux environment in the cloud, called a sandbox. Qube reads your uploaded material, runs code, and produces reports or charts there. You use it through conversations and the file panel; you do not need to learn Linux commands first.

Upload files from your computer when Qube needs them, and download outputs from the file panel when you want a local copy. Workspace files persist so you can use them in later conversations.

## Workspace files

Use files for uploaded research material, notebooks, reports, scripts, and requested artifacts. You can reference workspace files in a conversation, then decide which outputs should be saved for long-term use.

See [workspace files and research assets](/qube/workspace/files) for the file panel and the difference between files, factors, and strategies.

## Skills

Official Skills explain how Qube should query data, author factors, write strategies, manage schedules, and save reusable knowledge. Personal Skills and knowledge are user-scoped and can be used to add stable context to future tasks.

## Schedules

Qube schedules run a prompt in a new Qube conversation at each trigger. A schedule keeps its task and execution history. Preview trigger times before creating a recurring schedule, and review the resulting conversation when it runs.

<Note>
  A workspace file is not automatically a factor, strategy, version, or run. Use the dedicated Qube research workflow to create and manage those objects.
</Note>
